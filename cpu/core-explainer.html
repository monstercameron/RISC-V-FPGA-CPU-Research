Where does the FPGA fit into this picture?

The FPGA is a chip whose logic can be configured. Our SystemVerilog describes the circuit inside it: registers, calculation logic, control and connections. Today a simulator runs that description. Later, synthesis turns it into a configuration for a particular FPGA. The RAM can use memory blocks on that same chip.

Does “64-bit” mean 64 things happen at once?

No. Each integer register holds a 64-bit value: eight bytes. This core still handles one instruction at a time. A later vector unit will work on groups of values; its register size and physical arithmetic-lane count are separate choices.

Why can’t it run the LLM yet?

The first core has whole-number instructions. It still needs floating-point and vector facilities, a much larger memory system, and the full software graph. The LLM research describes a future workload. It does not mean this small CPU has already implemented it.

Is this animation the actual RTL running?

This is a teaching model of the implemented design. Each step explains a job; it is not one exact clock cycle or a live simulator trace. The Load lesson deliberately pauses to explain memory waiting. The linked verification record comes from the separate RTL simulation suite.

What happens when an instruction goes wrong?

The first core records the instruction address, reason and offending value, then stops issuing memory requests until reset. It does not save a result from the bad instruction. A later stage will add software trap handlers so the CPU can recover or report the fault through a real runtime.
