An original 64-bit RISC-V processor core

Atelier

Silicon, made in the open.

Atelier is a fully libre 64-bit RISC-V processor core: out-of-order, written in SystemVerilog, and developed in simulation against a sequential golden model. It is designed to compete with the best Arm cores per clock, on the workloads people run.

Evidence: simulation only

Current statusSource

What this is, and what it is not

Atelier is designed to compete with the best Arm cores. That is a design goal and a target we measure against, set per clock against an estimated Apple M6 reference. It is not a measured result.

Today it exists only in simulation. There is no silicon and no board result yet, and no hardware performance is claimed. Every number on this site comes from simulation of the design and says so.

Design goal

The per-clock goal is referenced to an Apple M6 estimate, bridged from laptop measurements. The reference is an estimate, not a measurement of an Apple M6, and the goal is a target, not a result.

Goals, in simulation

  • Met in simulation 7-Zip, a 10,000 MIPS single-thread rating at 4 GHz. On cpu-v0.18.0 at the deciding configuration (the full-size d22 kernel with the 7-Zip-matched CRC, a 4 MiB L2, 60 sampled pieces per phase): compress 2.211 MIPS/MHz (109% of its 2.02 goal; low end 2.072) and decompress 2.975 (120% of 2.47; low end 2.887). The average is 2.593 MIPS/MHz, or 10,372 MIPS at 4 GHz; the low ends average 2.48 (9,918 MIPS). The decompress goal is provisional: its laptop reference was measured under load and needs a quiet re-measure. Later versions were not measured at d22.
  • Open Ray and path tracing, against the Apple M6 reference. At the deciding configuration the last measured rates (0.19.0 with 64 B data lines) were 3.71 primary and 1.96 secondary rays per thousand clocks, against goals of 5.92 and 8.64: roughly 60% and 25%. Done: the benchmark (a TinyBVH traversal and a smallpt-style path tracer) with a checked scalar FP32 reference, the laptop measurement, F and D in the out-of-order core (0.17.0 to 0.17.4), the first vector step in order at the head of the reorder buffer (0.18.0), and the memory side for irregular access (64 B lines, the L2 prefetcher, and wider split-read answers, ready but not released). Left: out-of-order vector execution (SIMD step 2a), the vector coverage the kernels need (integer, mask, permute, gather and scatter, compaction), and a vectorized kernel measured at VLEN 128, 256 and 512 with lane-utilization counters. No Apple, Intel or AMD machine was measured on these workloads here; only cited figures exist.
  • Open JavaScript, 1.30x the laptop per clock. With the indirect-jump predictor and four instruction-cache ways (options of 0.19.1 and 0.19.3), 84.7% of the goal at the deciding configuration, and 91.4% with the bound measured for a fetch-directed prefetcher that is not yet built.

Sources: 7-Zip targets, ray-tracing targets, cpu/CONTINUATION.md and the journal.

Paused, 2026-11-22

Work paused on 22 November 2026 after the release of 0.21.0. When it resumes, each step is its own version, in this order:

  1. Wider split-read answers (ready to release as the next MINOR), then 16 data tags, more L2 misses in flight and a higher prefetcher fill cap.
  2. The front end: non-blocking instruction-line reads, then a fetch-directed prefetcher.
  3. Out-of-order vector execution (SIMD step 2a), then the rest of the vector coverage, for the ray-tracing goal.
  4. Privilege: machine mode in the out-of-order core, then counters, interrupts and WFI, then user and supervisor modes.

The full docket and the open questions are in cpu/CONTINUATION.md.

Libre principles

  • RTL, tests, scripts and their licences are in the repository. Original work is MIT licensed (LICENSE).
  • Third-party licences and notices are kept apart, in licenses/.
  • Firmware is planned, not yet built. A hardware-specific licence has not been chosen.
  • Each result cites the run that produced it in the journal, so it can be reproduced.

Build and test

Nothing is downloaded and no FPGA is needed. From the repository root:

python -B sim/cpu/suite.py --list
python -B sim/cpu/suite.py unit --jobs 1
python -B sim/cpu/suite.py release-patch --dry-run
python -B scripts/check_repo.py

Roadmap

Each stage has exit evidence, listed in cpu/architecture.md section 6. No dates are given.

  • Plan C1: a real execution environment (traps, interrupts, counters, user mode). Begun: machine-mode CSRs and traps exist as an option of the multicycle core (0.21.0).
  • Plan C2 to C4: scalar breadth, memory correctness, scalar floating point.
  • Plan C5 to C6: a complete vector engine and profile closure.
  • Plan C7: an FPGA proof on an exact part. No board run is claimed yet.

Target: RVA23U64, in stages. Not compliant today (cpu/architecture.md section 5).
